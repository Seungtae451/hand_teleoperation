# GeoRT 실시간 반응 진단 — 2026-10-18

학습 루프가 중단되거나 잘못된 체크포인트를 로딩했다는 증거는 없다. 그러나 공개 Quest 입력과
실시간 Quest 입력 사이에 손바닥 법선 축 부호가 반대로 나타나는 정합성 문제가 확인되어,
현재 공개 Quest 세 모델을 정상적인 데이터 수 비교의 최종 결과로 해석해서는 안 된다.
좌표계의 좌우성·handedness·출판된 좌표 변환 규약을 먼저 확인해야 한다.

## 1. 확인한 범위

- 네 모델 모두 원본 200 epoch를 완료했고 checkpoint hash가 실제 실행 로그와 일치한다.
- 원본 export는 `.eval()`을 호출하며 진단에서도 eval mode를 확인했다.
- 배치 추론의 첫 출력이 원본 `forward()` 단일 프레임 출력과 허용 오차 내에서 일치한다.
- 같은 로봇 FK 가중치가 네 모델에 사용됐다. 앞선 독립 FK 검사에서 평균 손끝 오차는
  약 2.17 mm였다. 현재 진단은 같은 FK hash를 사용하며 그 검사를 새로 실행한 것은 아니다.
- 학습 데이터·검증 데이터·실제 관찰 입력에서 각 최대 512프레임을 동일 간격으로 뽑아 비교했다.
- 실시간 입력은 `results/live-retargeting-x2117cq6/quest_input.jsonl`의 완전한 줄만 복사한
  snapshot이며 유효 오른손 4,989프레임이다. 원본 기록은 보존했다.
- 보존된 test 11,209프레임은 이번 진단에 사용하지 않았다. 재학습·튜닝은 하지 않았다.

## 2. 공개 입력과 실시간 입력의 법선 방향 불일치

기존 GeoRT 원본 helper로 손목 원점과 MCP 기반 축을 만든 뒤 비교했다.
공개 10k의 엄지 손끝 X가 양수인 비율은 0.07%, 실제 Quest는 94.23%다.
새끼 MCP의 평균 X는 공개 데이터 -11.95 mm, 실제 입력 +12.14 mm다.
손목→중지 MCP 길이는 공개 약 94.2 mm, 실제 약 95.7 mm여서 단순 1,000배 단위 오류는
관찰되지 않는다. 다만 실제 단위의 독립 측정 검증을 대체하는 것은 아니다.

실시간 512프레임의 각 손끝에 대해 해당 학습 손끝 점군의 최근접 거리를 계산했다.

| 모델 학습 데이터 | 원래 학습 점군까지 평균 거리 | 진단용 X 반전 점군까지 평균 거리 |
|---|---:|---:|
| 공식 3,498 | 23.08 mm | 35.76 mm |
| 공개 Quest 1,000 | 35.16 mm | 5.86 mm |
| 공개 Quest 3,498 | 33.78 mm | 4.72 mm |
| 공개 Quest 10,000 | 33.16 mm | 3.94 mm |

X 반전은 determinant -1인 반사이며 일반 회전 보정과 다르다. **원인 확인용 가상 실험으로만
계산했고 학습 데이터·실시간 파이프라인·체크포인트에는 적용하지 않았다.**
이 수치는 반전한 모델의 성능이나 성공률이 아니다.
좌표계 변환의 좌우성, 손 라벨, 손 자세 분포 중 무엇이 원인인지 단독으로 확정하지는 못한다.
다만 공개 데이터의 기하와 현재 실시간 입력이 반사에 가까운 차이를 가진다는 강한 증거다.

앞선 79,244프레임 검증은 배열·유한값·길이·퇴화 여부를 검사한 것이었다.
해부학적 방향과 실제 Quest 입력의 좌우성 정합성까지 검증한 것으로 간주한 것은 부족했다.
해당 수량은 기본 기하 검사를 통과한 행 수로 유지하고, 학습 입력 의미 검증은 별개로 진행해야 한다.

공개 Quest 10k 모델의 512개 실제 입력에서 손가락 입력의 약 79.5%는 학습 손끝 점군으로부터
5 mm 이상 떨어졌다. 같은 모델의 공개 validation에서는 약 0.2%였다.
관절 출력이 한계 근처 5% 구간에 놓인 비율도 공개 validation 약 7.1%, 실제 입력 약 22.5%다.
이는 현재 실시간 입력이 학습 분포와 다르고 출력 포화가 증가하는 현상과 일치한다.
둘 사이의 정확한 인과관계는 데이터 의미를 바로잡은 통제 실험으로 확인해야 한다.

## 3. 원본 학습 목표와 화면의 손 모양은 같지 않다

GeoRT 원본은 사람 관절각 정답을 주고 그대로 따라 하도록 학습하지 않는다.
코드의 chamfer는 로봇 손끝 점군과의 분포 대응을 계산하며,
`robot_tip(frame) == human_tip(frame)`라는 프레임별 정답 손실이 아니다.
손가락 점군도 독립적으로 재샘플링된다.
각 손가락 네트워크는 손끝 XYZ 3개를 받아 로봇 관절 4개를 출력한다.
같은 손끝 위치를 만드는 관절 구성이 여러 개일 수 있어 전체 손가락 자세 일치를 보장하지 않는다.
이는 현재 구현에 새로 추가한 규칙이 아니라 원본 구조의 성질이다.

로그에서 direction 항은 공식 모델 0.0045→-0.9409,
공개 10k 모델 -0.1193→-0.8920으로 변했다. 최적화가 진행된 증거이지만
이 값은 epoch 평균이나 validation 오차가 아닌 첫 minibatch 로그다.
손 모양의 정확도·충분한 수렴을 증명하지 않는다.

진단의 raw 손끝 대응 거리에는 사람 손목과 로봇 palm이라는 서로 다른 원점 및 손 크기 차이가
포함된다. 이를 독립 ground truth 기반 정확도 지표로 해석하지 않는다.

## 4. 제어 지연도 관찰에 섞인다

실시간 TRACKING 로그에서 매 tick의 20개 관절 중 최대 차이를 계산한 뒤 평균했다.

| 모델 | 모델 목표→명령 차이 | 명령→실제 관절 차이 |
|---|---:|---:|
| 공식 3,498 | 0.471 rad | 0.017 rad |
| Quest 1k | 0.579 rad | 0.017 rad |
| Quest 3,498 | 0.473 rad | 0.016 rad |
| Quest 10k | 0.524 rad | 0.016 rad |

모델 목표의 tick 간 변화가 공통 π rad/s 제한의 20 ms 허용량을 초과한 비율은 약 33–36%다.
현재 화면의 느린 반응에는 속도 제한으로 목표를 따라가는 지연이 포함된다.
목표 자체가 잘못된 손 모양을 내는 문제와 별개로 봐야 한다.
속도 제한을 제거해 모델 문제를 숨기거나 관절 범위를 임의로 바꾸지는 않았다.
표의 차이를 직접 시간 지연 초 단위로 환산해서는 안 된다.

## 5. 데이터 커버리지 해석 시 주의

10k 공개 데이터에서 thumb-index 15 mm 미만 후보는 508프레임이지만 thumb-ring은 5,
thumb-pinky는 0이다. 실제 입력 snapshot에서는 각각 66, 99, 35다.
데이터 양만 늘리는 것으로 드문 동작 커버리지가 충분해진다고 볼 수 없다.
이 기준은 원본 pinch 거리와 맞춘 기하 후보이며 정답 동작 라벨이 아니다.

최초 진단 JSON의 `fist_candidate_count_pip60_mcp45`는 MCP 굽힘 부호에 의존한다.
부호 정합성이 의심되는 공개 입력에서 해당 값 0을 근거로 “주먹 데이터가 없다”고 말할 수 없다.
MCP 절댓값 기준으로는 공개 10k에서 120프레임, 실제 snapshot에서 670프레임이다.

## 6. 다음 순서

1. 공개 데이터의 SDK/좌표 변환 출처와 오른손 라벨을 확인하고 펼친 손·굴곡 샘플을 시각 검증한다.
2. 확인한 규약에 따른 dataset adapter를 별도 작성한다. 원본 알고리즘은 유지한다.
3. 원본과 교정 입력을 별도로 보존하고 공개 Quest 세 조건을 같은 seed·200 epoch로 다시 학습한다.
   공식 human_alex 입력은 이번 반사 징후 대상과 다르므로 기존 공식 모델을 보존한다.
4. 먼저 직접 모델 목표의 자세 대응을 검증하고, 이후 공통 제어기에 연결해 동적 반응을 비교한다.

데이터 의미를 확인하기 전에는 단순 epoch 증가나 30k 확장으로 해결하려고 하지 않는 것이 적절하다.
현재 공개 Quest 모델은 좌표 정합성 검증 대기 상태의 실험 결과로 취급한다.

진단 원자료:
`results/geort-diagnosis-nsinlfay/diagnosis.json`,
`results/geort-diagnosis-nsinlfay/chirality_diagnostic.json`.
기본 진단 재실행: `CUDA_VISIBLE_DEVICES=1 .venv-geort/bin/python scripts/diagnose_geort_models.py`.
실시간 기록이 계속 늘면 새 snapshot과 수치는 달라진다.
